Skill 类型学 · Skills Over MCP

Agent Skills 类型全景

官方规范并不给 Skill 分类型——所有 Skill 都是同一种格式：一个目录、一个 SKILL.md、若干可选附带文件。所谓「类型」，是内容形态的差异，决定它能否通过远程 MCP 直接消费。

依据 MCP 官方 Skills 扩展（SEP-2640）与 skillsovermcp.com 托管服务的实际行为整理。

统一格式：目录 + SKILL.md 可选附带：references / scripts / examples / assets 8 种内容形态
01 — 八种内容形态

规则之外，还有七种形态

按「SKILL.md 里装的是什么」划分。前七类本质是文本指令，远程接入后由客户端已有能力执行；第八类携带真实代码，执行边界受官方安全规则约束。

TYPE 01
规则清单型

SKILL.md 内是规则、步骤与检查清单，AI 读取后按规则执行。最经典、数量最多的形态。

构成：SKILL.md 单文件即可
例：write-like-a-human · review-pr · triage-bug

远程直接可用
TYPE 02
知识参考型

主体在 references/ 目录：术语表、风格指南、行业知识、检查清单，SKILL.md 只是入口索引。

构成：SKILL.md + references/*.md
例：review-pr 附带的 checklist.md

远程直接可用
TYPE 03
模板产出型

定义输出模板、文档结构、格式规范——邮件、报告、代码骨架，产出物照模板生成。

构成：SKILL.md + examples/ 模板
例：报告结构、邮件模板类 Skill

远程直接可用
TYPE 04
示例驱动型

以输入输出范例为主，靠 few-shot 示例教模型模仿，比规则描述更直接。

构成：SKILL.md + examples/ 范例对
例：风格转换、数据标注类 Skill

远程直接可用
TYPE 05
工具指引型

教模型「怎么用好某个已有工具或 API」——参数、调用顺序、注意事项，不携带工具本身。

构成：SKILL.md 使用说明
例：数据库查询、CLI 工具用法类 Skill

远程直接可用
TYPE 06
角色风格型

定义语气、人设与写作风格，让模型以特定声音输出，常见于品牌内容或个人化写作。

构成：SKILL.md + references/ 风格样本
例：spencers-writing-style

远程直接可用
TYPE 07
工作流 SOP 型

多步骤标准流程、判断分支、阶段门，把一段完整作业拆成可逐步执行的操作序列。

构成：SKILL.md 分步定义
例：发布流程、质检 SOP 类 Skill

远程直接可用
TYPE 08
脚本执行型

携带 scripts/ 真实代码，需要运行。内容可以远程分发，但执行受「无隐式本地执行」规则约束。

构成：SKILL.md + scripts/*.py|.sh
例：数据处理、自动化脚本类 Skill

可分发 · 执行需审批
02 — 统一格式

格式只有一种，差异全在内容

官方规范（Agent Skills / SEP-2640）对 Skill 的格式约束极少，这正是它易于远程分发的原因。

SKILL 的物理结构
your-skill/
├─ SKILL.md          # 必需：规则本体，frontmatter 至少含 name + description
├─ references/     # 可选：清单、风格指南、知识文件
│   └─ checklist.md
├─ scripts/        # 可选：可执行脚本
│   └─ extract.py
├─ examples/       # 可选：输入输出范例、模板
└─ assets/         # 可选：模板、图片等资产

规范只规定两条硬约束：Skill 是一个目录，目录内必须有 SKILL.md；SKILL.md 必须以 YAML frontmatter 开头，至少包含 name 与 description。其余一切内容都是可选的。

description 决定 AI 何时调用它，正文决定它怎么做——这个结构让「远程提供方法」成为可能。

远程 MCP 只分发规则文本（SKILL.md 与附带文件），不执行任何代码。执行永远发生在客户端本地，由你的工具、权限与审批决定。

03 — 远程适用性

能不能远程用，取决于要不要跑代码

判断标准只有一条：Skill 的产出是「让 AI 知道怎么做」，还是「让某个脚本跑起来」。

文本指令类 · 远程直接可用

规则、知识、模板、示例、指引、风格、流程——全部是文本。接上 MCP 地址即生效，执行复用客户端已有能力，零本地安装。

  • 01 规则清单 · 02 知识参考 · 03 模板产出
  • 04 示例驱动 · 05 工具指引 · 06 角色风格 · 07 工作流 SOP
  • 接入后下次连接自动更新，无需重新部署
代码执行类 · 可分发，执行受审批门槛

脚本内容可通过 MCP 拉取到本地，但不会自动运行。官方规则要求：未经逐 Skill 的明确用户审批，宿主不得让技能内容触发本地代码执行。

  • 08 脚本执行型：内容远程可读，运行须本地环境
  • frontmatter 声明的钩子 / 脚本字段必须忽略或加审批门槛
  • 正文指示模型调用代码执行工具，同样需要审批
04 — 官方安全边界

远程技能被规范视为更高风险面

MCP 官方 Skills 扩展（SEP-2640）在 Security Considerations 中明确了对远程技能的四条硬规则。

RULE 01

技能内容是不可信输入

MCP 提供的技能内容按不可信模型输入处理，与任何服务端文本一样接受提示注入防御。服务端已连接，不代表它的内容可信——远程技能比远程工具调用风险更高。

来源：Security Considerations — Skill content is untrusted input
RULE 02

无隐式本地执行

未经逐 Skill 的明确用户审批，宿主不得让技能内容触发本地代码执行。覆盖两类：frontmatter 声明的钩子与脚本字段（必须忽略或审批）；正文中指示模型调用代码执行工具的指令（同样加审批门槛）。

来源：Security Considerations — No implicit local execution
RULE 03

内容绑定审批

审批绑定到技能的文件清单（每个 uri + digest）。清单一变——文件轮换、增删——既有审批立即失效，必须重新确认后才能加载或执行。

来源：Security Considerations — Content-bound approval
RULE 04

技能是数据，不是指令

技能资源不比其它上下文更高权威，是否加载完全由用户策略决定。宿主不得把远程技能当作本地文件系统技能同等信任，也不得让同名技能静默覆盖本地技能。

来源：Security Considerations — Skills are data, not directives
